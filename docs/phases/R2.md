# R2 — Session-Aware Query Rewriting

> Status: **COMPLETE (code + gates + live acceptance) — 2026-08-26**
> Depends on: R1 (golden set + harness)
> Plan source: [RAG upgrade plan §6](../blueprint/RAG_UPGRADE_PLAN.md)

## Goal

Make follow-up questions ("How do I fix it?", "What about the RU-500?") retrieve
as if the user had written the full question. Before R2 the RAG path embedded the
raw follow-up — and the RAG endpoint could not even receive a session id, so
conversation context was unreachable, not merely unused.

## Scope

**In:** rewrite module · retrieve() session plumbing · `sessionId` on the RAG
endpoint · hybrid-path context reuse · config flags · eval-harness routing
through retrieve().

**Out:** R3 hybrid retrieval · R4 chunking/metadata (separate phases); advisor
session support (no session model for incidents yet — the plumbing is inherited,
the wiring waits for a use case).

- Fake-mode harness regression: identical metrics table to R1 baseline

  real rewrite fires.
- API: `POST /v1/rag/query {"question": "What about it?", "sessionId": …}` →

  identifiers; unknown/cross-tenant session ids → 200 with zero rewrite calls.

## Decisions taken

1. **Typed catch, not broad** — `rewrite_query` catches `LLMError` only: the
   OpenAI-compatible client wraps every failure (transport, HTTP, parse) into
   `LLMError`, so the plan's "any exception → question unchanged" is satisfied
   without a broad except.
2. **Rewrite inside `retrieve()`, not at the API layer** — one choke point;
   `advise()` inherits the plumbing for free even though it passes no turns
   today.
3. **Turn slicing in `retrieve()` (config-driven)** — `rewrite_query` stays a
   pure function of its inputs; the window is policy, not mechanism.
4. **`rag_recent_turns` in `api/flow.py`** — the SQL path's non-blocking session
   helpers already lived there; both routers share one implementation.
5. **`_unified_rag_part` at module level** — first attempt as a closure pushed
   `build_query_router` over the statement budget (PLR0915); hoisting it out
   kept `unified()` readable and the linter honest.
6. **Empty-string fake generate = automatic fallback** — `HashEmbedLLM.generate`
   returning `""` makes fake-mode eval exercise exactly the v1 path with zero
   special-casing; the scripted `HashScriptedLLM` covers the rewrite-on path.

## Deviations from the plan doc

- Plan sketched the API field as `session_id`; shipped as `sessionId` — the
  wire contract is camelCase everywhere else (`sessionId` on SQL/unified
  requests), consistency wins.
- Plan's acceptance (followup ≥ +0.3) cannot be measured with hash embeddings
  (no LLM): split into offline mechanism proof (done, deterministic) + live
  number (owner, same split as R1's baseline).
