# R1 — Golden Set + Retrieval Eval Harness

> Status: **COMPLETE (code + gates + fake-mode run) — 2026-08-26 · live baseline pending owner API key**
> Depends on: v1.0 (Phase 0–7)
> Plan source: [RAG upgrade plan §5](../blueprint/RAG_UPGRADE_PLAN.md)

## Goal

Stop flying blind on RAG retrieval quality. Before touching any retrieval code
(R2 rewrite, R3 hybrid, R4 chunking), build the measurement instrument: a
deterministic document corpus, a tagged golden set, and a Recall@k/MRR harness
that runs offline (CI-shaped) and live (real embeddings + Postgres).

**Zero production-path changes** — R1 is purely additive; the answering pipeline
is untouched.

## Scope

**In:** demo doc corpus (4 manuals) · corpus-lock tests · golden set (36 cases) ·
eval core (models/scoring/metrics) · CLI harness (`--fake`/`--live`) ·
deterministic hash embedder · seeding driver · baseline report template.

**Out:** any change to `rag/rag_flow.py`, `rag/store.py`, `api/*` (reserved for
R2–R4); RAGAS or external eval frameworks (deferred); real live-baseline numbers
(needs `LLM_API_KEY` — owner-run).

```
| overall    | 36    | 0.54 | 0.42 | 0.64 | 0.67 | 0.81 |
| followup   | 3     | 0.06 | 0.00 | 0.00 | 0.00 | 0.33 |
| identifier | 10    | 0.80 | 0.70 | 0.90 | 0.90 | 1.00 |
| multi-hop  | 3     | 0.42 | 0.33 | 0.33 | 0.67 | 0.67 |
| paraphrase | 8     | 0.50 | 0.25 | 0.75 | 0.75 | 0.88 |
| procedure  | 6     | 0.66 | 0.50 | 0.83 | 0.83 | 1.00 |
| table      | 6     | 0.36 | 0.33 | 0.33 | 0.33 | 0.50 |
```

- The smoke run already exposes the predicted failure shape (the plan's thesis,
  measured by our own harness):
  - **followup R@5 = 0.00** — bare "how do I fix it?" retrieves nothing → R2's target
  - **table R@5 = 0.33** — spec lookups land on wrong sections → R4's target
  - **identifier R@5 = 0.90 is artificially high** — hash embeddings are lexical,
    which is exactly what BM25 (R3) adds; real dense embeddings are expected to
    drop this materially. That drop, measured, is R3's headline number
- `tests/test_rag_eval_core.py` (14 tests): golden-file contract, hit-scoring
  semantics (any-of documents, case-insensitive section, 1-based ranks),
  Recall@k/MRR math, `HashEmbedLLM` protocol conformance + determinism,
  end-to-end fake run determinism, identifier ≥ followup sanity

## Decisions taken

1. **Section-based expectations, not page** — markdown docs parse to a single
   page (page 1), so page is useless as a locator; `section` (case-insensitive
   substring) is the real anchor. Page matching stays in the model for
   PDF-shaped futures (R4).
2. **`documents:` any-of lists** — shared facts (E-302, TS-001 exist in both
   versions) accept either sibling until R4's supersede lifecycle makes version
   selection deterministic; version-exclusive facts (E-304, A-104) pin one doc
   today.
3. **Hash embeddings over zero-vectors** — `tests/fakes.py::FakeLLM.embed`
   returns all-zeros, which makes every cosine identical and fake-mode search
   meaningless. `HashEmbedLLM` (bag-of-words md5-indexed into 1536 dims)
   approximates lexical overlap: deterministic, offline, and good enough to
   smoke the harness shape. Clearly labeled "not a baseline" in the report.
4. **`tools/` as a package with strict typing** — no relaxed executionEnvironment
   (unlike `demo/`); the harness is long-lived measurement infrastructure, not a
   throwaway seed script, so it gets the full basedpyright `all` treatment.
5. **Followup cases carry dormant `context`** — scored against the bare question
   now (that IS the v1 behavior being measured); the field exists so post-R2
   evaluation can score the same cases with rewrite enabled without touching
   the golden set file.
6. **T201 under `tools/**`** — CLI prints its report; same rationale as the
   pre-existing `demo/**` allowance.

## Deviations from the plan doc

- Plan sketched `tools/rag_eval.py` as a script; shipped as `tools/` package
  (`rag_eval.py` CLI + `rag_eval_core.py` importable pure core) so tests import
  scoring without invoking a CLI, and the 250-LOC ceiling holds per file.
- Plan's "seed via `seed_demo.py` leg or new `seed_docs.py`" — chose the new
  module: doc seeding must run against any `RagStore` (in-memory for fake mode),
  which the telemetry-oriented `seed_demo.main()` can't.
