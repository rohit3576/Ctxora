# R4 — Structure-Aware Chunking, Version Lifecycle, and Filtered Retrieval

> Status: **COMPLETE (code + gates + live acceptance) — 2026-08-27**
> Depends on: R1 (golden set + harness), R2 (session-aware rewriting)
> Plan source: [RAG upgrade plan](../blueprint/RAG_UPGRADE_PLAN.md)

## Goal

Make the RAG corpus able to fail — then fix it. R1's live baseline exposed
that the demo corpus was too easy: `table` = 1.00 only because every table
fit inside one section, and both manual versions stayed ACTIVE forever, so
retrieval could quote an obsolete procedure with nothing to stop it. R4
built the harder corpus, measured the pain, then shipped the structural
fixes: parent/child chunking, a version lifecycle, and deterministic
metadata filters.

## Scope

**In:** corpus expansion with split probes + version-pinned golden cases
(4a) · live before-baseline (4b) · one additive schema migration (4c) ·
chunker v2 behind `chunking_v2` (4d) · ACTIVE/SUPERSEDED lifecycle (4e) ·
typed `RagFilters` end-to-end (4f) · final live re-baseline + this doc (4g).

**Out:** R3 hybrid retrieval (deferred again — post-R4 there is no
measurable headroom on this corpus; see
[`docs/tuning/rag_r4_final.md`](../tuning/rag_r4_final.md)) · reranking or
section-priority scoring (rank-1 behavior noted below) · advisor filters.

## Known behavior (accepted)

- **Version-case rank 1 is section-precision, not attribution**: rank-1
  chunks belong to the same newest revision (e.g. DS-200 v2 *Gasket
  Replacement* also says "50 Nm" and outranks Maintenance Procedure).
  The 4a target table's "version R@1 → 1.00" conflated the two; the
  plan's actual acceptance (cite newest only) holds 100%. Fixing rank-1
  section precision is reranking work — out of R4 scope.
- v1 chunking path (`chunking_v2: false`) retained for rollback; mixed
  v1/v2 stores keep answering (legacy merge proven in tests).

## Decisions taken

1. **Parents never embed** — children are the ranking surface, parents
   the answering surface; upload cost stays proportional to children.
2. **Born-superseded over rejection** — uploading an older version
   stores it as SUPERSEDED rather than erroring: history is preserved,
   stale answers stay impossible.
3. **One containment contract** — `deviceModel`/`firmwareVersion` fold
   into the same metadata map free-form filters use; PG `@>` and the
   fake apply identical semantics, so the contract is testable offline.
4. **Golden maintenance follows behavior changes** — re-pinning the 3
   old-version cases (with canaries) instead of deleting them keeps the
   slices comparable and turns regressions into test failures.
5. **R3 stays deferred** — zero misses at R@10 leave no measured
   justification for hybrid retrieval on this corpus; revisit only with
   a corpus where query-term coverage actually fails.
